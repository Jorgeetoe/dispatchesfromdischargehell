# Hugo Migration: Dispatches from Discharge Hell

## What Changed

This project has been migrated from **static HTML/FTP deployment** to **Hugo + Cloudflare Pages**.

### Before
- Content format: HTML files
- Templates: None (each file is standalone)
- Hosting: Hostinger (paid shared hosting)
- Deployment: FTP (manual password, connection issues)
- Blog listing: Manual HTML list
- Build: None (static HTML)

### After
- Content format: Markdown with YAML front matter
- Templates: Shared Hugo layouts (one change = site-wide)
- Hosting: Cloudflare Pages (free, global CDN)
- Deployment: `git push` (automatic, no credentials)
- Blog listing: Auto-generated by Hugo
- Build: `hugo build` (includes minification, cleanup)

## Quick Start

### Local Development

1. **Install Hugo** (if not already installed):
   ```bash
   brew install hugo
   ```

2. **Start the dev server**:
   ```bash
   cd hugo
   hugo server
   ```
   Visit `http://localhost:1313` to preview

3. **Create a new post**:
   ```bash
   cd hugo
   hugo new blog/posts/YYYY-MM-DD-my-post-title.md
   ```
   Edit the markdown file and the post appears live in the preview

4. **Build for production**:
   ```bash
   cd hugo
   hugo --gc --minify
   ```
   Output goes to `hugo/public/`

## Publishing a New Post

### Option 1: Using the `/publish` Slash Command (Recommended)

Jorge opens Claude Code and uses the `/publish` command:
```
/publish
[paste article content]
```

Claude Code:
1. Reads the article markdown and metadata
2. Generates a `.md` file with YAML front matter
3. Saves it to `hugo/content/blog/posts/YYYY-MM-DD-slug.md`
4. Commits with git
5. Pushes to GitHub
6. Cloudflare Pages auto-builds and deploys

### Option 2: Manual Git Workflow

```bash
# 1. Create new post
cd hugo

# 2. Edit the file

# 4. Commit and push
git add hugo/content/blog/posts/YYYY-MM-DD-my-post-title.md
git commit -m "Publish: My Post Title"
git push

# 5. Cloudflare Pages auto-deploys within 2-3 minutes
```

## Deployment: GitHub + Cloudflare Pages

### Setup (First Time Only)

1. **GitHub Account**
   - Create a GitHub account at github.com (if needed)
   - Create a private repo: `DispatchesFromDischargeHell`
   - Clone this repo to your GitHub account

2. **Cloudflare Account**
   - Sign up at cloudflare.com (free account)
   - Go to Workers & Pages
   - Click "Create Application" → "Pages"
   - Connect your GitHub repo
   - Configure build settings:
     - Framework: Hugo
     - Build command: `hugo --gc --minify`
     - Build output directory: `hugo/public`
     - Root directory: (leave blank)

3. **DNS**
   - Cloudflare provides nameservers
   - Update your domain registrar to point to Cloudflare's nameservers
   - Add custom domain in Cloudflare Pages settings

### How Deployment Works

Every `git push` to `main` triggers:
1. GitHub detects the push
2. GitHub Actions runs the workflow
3. Hugo builds the site (`hugo --gc --minify`)
4. Cloudflare Pages receives the `hugo/public/` folder
5. Site goes live in 2-3 minutes

## Troubleshooting

### Build fails locally
```bash
cd hugo
hugo --logLevel debug
```

### Post not showing up
- Check `date` is not in the future
- Check `draft: false` (or remove the draft field)
- Verify filename matches pattern: `YYYY-MM-DD-slug.md`

### Site looks broken on Cloudflare Pages
- Check Cloudflare Pages build logs
- Verify `hugo/public/` was generated: `ls hugo/public/index.html`
- Check CSS/JS paths in `hugo/layouts/_default/baseof.html` are correct

### GitHub push fails
```bash
git status           # Check what's staged
git add .            # Stage all changes
git commit -m "..."  # Create commit
git push             # Push to GitHub
```

## FAQ

**Q: How do I preview posts before publishing?**
A: Use `hugo server` locally, or create a PR on GitHub and Cloudflare Pages will show a preview deployment.

**Q: Can I use the old HTML files?**
A: No, but they're backed up in the `site/` folder. The new workflow is Markdown-only.

**Q: What if I need to make site-wide changes (header, footer)?**
A: Edit once in `hugo/layouts/partials/header.html` or `hugo/layouts/partials/footer.html`. Changes apply everywhere.

**Q: How do I cancel Hostinger?**
A: After confirming the Cloudflare site is live and stable, cancel from the Hostinger hpanel. No rush.

**Q: Can I use a custom domain?**
A: Yes! Add it in Cloudflare Pages settings. Cloudflare provides free SSL/TLS.
